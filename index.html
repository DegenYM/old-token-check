    How it works

    1. A verified list, not a guess. Official migrations such as MATIC → POL, MKR → SKY and GNT → GLM. Every path in the registry names the old token, the new one, the official migrator and the exact calls. Before listing, each was simulated from a real holder and checked against official docs. Candidates that failed are kept out.
    2. Balances straight from the chain. We read your old-token balances with balanceOf through Multicall3 on each chain. Explorer holder lists for old tokens are often stale, so we never rely on them.
    3. A dry run from your address. For every balance we find, we simulate the full migration (usually approve, then migrate) from your address with your whole balance, using eth_simulateV1 or, where a chain doesn't support it, eth_call with a state override. You only see "Ready" when the simulation succeeds and you receive the new token.
    4. You send the transactions. Each result lists the Etherscan pages, functions and values to paste, plus the official app when one exists. This site never asks to connect.

    Simulations run on the latest block. If a contract is paused, closed or runs out of payout balance after that, a real transaction can still fail.
